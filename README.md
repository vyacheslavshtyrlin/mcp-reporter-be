# MCP Reporter Backend

Backend-сервис, который превращает открытые статистические данные в проверяемые отчёты и предоставляет их AI-клиентам через [Model Context Protocol (MCP)](https://modelcontextprotocol.io/).

Проект нужен для сценариев, где модель должна не придумывать числа и не разбирать внешний API самостоятельно, а вызвать типизированный инструмент, получить данные из известного источника и выполнить детерминированный расчёт на backend. Первый источник — [World Development Indicators](https://databank.worldbank.org/source/world-development-indicators) Всемирного банка.

> Проект учебный и production-like. Сейчас он предназначен для локального использования: аутентификация, постоянное хранилище и публичный deployment ещё не реализованы.

## Что уже умеет сервис

- показывает доступные наборы данных, измерения и показатели;
- получает полный временной ряд из World Bank с пагинацией, повторами временных ошибок и runtime-валидацией;
- строит отчёты `time_series` и `period_change`;
- сохраняет происхождение данных, покрытие и предупреждения о пропусках;
- предоставляет MCP Streamable HTTP endpoint `http://127.0.0.1:3000/mcp`;
- возвращает типизированные безопасные ошибки вместо внутренних деталей.

Поддерживается dataset `world-bank / 2` (`World Development Indicators`) и пять показателей: население, ВВП на душу населения, рост ВВП, инфляция и безработица.

## Как это работает

```text
AI-клиент
  → MCP Streamable HTTP (/mcp)
  → каталог или выполнение отчёта
  → WorldBankAdapter
  → World Bank API
  → валидация и нормализация
  → детерминированный расчёт
  → структурированный MCP-результат
```

MCP-слой остаётся транспортной границей: он валидирует параметры, вызывает application services и переводит ошибки. Получение внешних данных, расчёты и жизненный цикл запуска разделены между NestJS-модулями `Sources`, `Datasets`, `Reports` и `Execution`.

## MCP tools

| Tool                    | Назначение                                                        |
| ----------------------- | ----------------------------------------------------------------- |
| `list_datasets`         | Список наборов данных зарегистрированного источника               |
| `describe_dataset`      | Поля, показатели, возможности и версия схемы dataset              |
| `list_dimension_values` | Поиск и пагинация значений измерения, например кодов стран        |
| `list_measures`         | Поиск показателей и поддерживаемых ими операций                    |
| `run_report`            | Валидация и синхронное выполнение отчёта                          |
| `get_report_run`        | Статус запуска и следующая страница результата                    |

Полный порядок вызовов и пример определения отчёта находятся в [руководстве по использованию](./docs/USAGE.md).

## Быстрый старт

Требуются Node.js `>=24.21.0 <25` и npm `>=11.19.0 <12`; рекомендуемые версии — Node.js `24.21.0` и npm `11.19.0`. Точные ограничения закреплены в `.nvmrc`, `package.json` и `package-lock.json`.

```bash
npm ci
cp .env.example .env
npm run start:dev
```

В PowerShell вместо `cp` можно выполнить:

```powershell
Copy-Item .env.example .env
```

После запуска доступны:

- healthcheck: `GET http://127.0.0.1:3000/health`;
- MCP endpoint: `http://127.0.0.1:3000/mcp`.

Для обращения к `/mcp` нужен MCP-клиент с поддержкой Streamable HTTP. Endpoint не является обычным REST API и по умолчанию слушает только loopback-интерфейс.

## Проверки

```bash
npm run check
```

Команда последовательно запускает проверку форматирования, lint, typecheck, unit-тесты с coverage, e2e-тесты через настоящий MCP-клиент и production build. Unit/e2e-наборы не обращаются к живому World Bank API; live-проверка выполняется отдельно и вручную.

Отдельные команды:

```bash
npm test
npm run test:e2e
npm run test:cov
npm run typecheck
npm run build
```

## Ограничения текущей версии

- одновременно хранится не более 100 запусков: при заполнении вытесняется самый старый завершённый запуск, а если вся ёмкость занята активными — новый запуск временно отклоняется;
- все оставшиеся запуски теряются при перезапуске процесса;
- выполнение идёт inline с общим deadline 30 секунд;
- endpoint не имеет production-аутентификации и не должен публиковаться во внешнюю сеть;
- доступен один реальный источник и ограниченный каталог показателей;
- результат зависит от доступности World Bank API, но частичный ответ источника не считается успешным отчётом.
