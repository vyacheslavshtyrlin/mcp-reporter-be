Этот файл фиксирует согласованный backlog проекта. Архитектурные решения находятся в `mcp_reporting_design.md`, правила работы агента — в `AGENTS.md`.

Статусы:

- `[ ]` — не начато;
- `[>]` — выполняется;

- `[!]` — заблокировано или требует решения.

После завершения Task агент обновляет её статус только после выполнения относящихся к ней проверок. Новая крупная работа сначала согласуется в чате как Epic.

## EPIC-001 — Интеграция World Bank

**Статус:** завершён.

**Цель:** получить через единый контракт проверенные данные World Development Indicators и вернуть полный `RecordBatch`, не раскрывая ядру HTTP и пагинацию World Bank.

**Входит:** HTTP-клиент, runtime-валидация, нормализация, пагинация, каталог первого набора и пяти показателей, адаптер, обработка ошибок, NestJS DI и автоматические тесты.

**Не входит:** MCP tools, сохранение в PostgreSQL, расчёт отчётов, второй источник, Redis, очереди и микросервисы.

### Feature 1 — Исследование API и общий контракт источников

- [x] **WB-01 — Зафиксировать ответы World Bank.** Сохранить небольшие fixtures успешных страниц, страны/агрегата, метаданных показателя и API-ошибки; описать наблюдаемые особенности API.
- [x] **WB-02 — Определить контракты источника.** Создать `DataQuery`, `DatasetSchema`, `RecordBatch`, `DataSourceAdapter` и типизированные `SourceError` без привязки ядра к World Bank.

### Feature 2 — Надёжное получение данных World Bank

- [x] **WB-03 — Реализовать HTTP-клиент.** Закрепить HTTPS origin, безопасно собирать URL, поддержать timeout и отмену, преобразовать транспортные сбои в `SourceError`.
- [x] **WB-04 — Валидировать и нормализовать одну страницу.** Проверять `unknown` через Zod, распознавать API-ошибку при HTTP 200 и преобразовывать наблюдения в плоские записи.
- [x] **WB-05 — Загрузить все страницы.** Последовательно получить страницы по метаданным, проверить их согласованность, объединить записи и не возвращать частичный результат при ошибке или отмене.
- [x] **WB-06 — Проверить целостность ряда.** Отсортировать записи, обнаруживать дубликаты ключа `countryCode + indicatorCode + year`, сохранить footnotes и подготовить сведения о покрытии.
- [x] **WB-07 — Добавить ограниченные повторы запросов.** Повторять только временные ошибки с лимитом попыток и backoff, уважать `AbortSignal`; покрыть политику тестами без реальных задержек и сети.

### Feature 3 — Каталог и NestJS-адаптер

- [x] **DEV-00 — Обновить среду Node.js.** Закрепить Node.js 24.21.0 и npm 11.19.0 в `.nvmrc`, `packageManager`, `engines`, lockfile и документации; версия удовлетворяет требованиям Nest schematics.
- [x] **DEV-01 — Подключить воспроизводимый Nest CLI.** Установить точную совместимую версию `@nestjs/cli` в `devDependencies`, добавить `nest-cli.json`, проверить `npm exec nest -- generate --help` и пробную генерацию через `--dry-run`.
- [x] **WB-08 — Создать `SourcesModule`.** Сгенерировать Nest module/provider через CLI, зарегистрировать HTTP-клиент и адаптер через runtime DI-токен, явно настроить exports/imports.
- [x] **WB-09 — Реализовать каталог World Development Indicators.** Описать dataset `source=2`, пять согласованных показателей и операции; возвращать только страны, исключая агрегаты.
- [x] **WB-10 — Собрать `WorldBankAdapter`.** Реализовать методы `DataSourceAdapter`, проверку запроса и лимитов, формирование полного `RecordBatch` с provenance и coverage.
- [x] **WB-11 — Добавить contract-тесты адаптера.** Проверить каталог и `fetchRecords` на fixtures через публичный контракт; live World Bank оставить отдельной ручной opt-in проверкой.
- [x] **BUG-WB-01 — Поддержать несколько показателей в актуальном World Bank API.** Нормализовать ожидаемый `sourceid: null` к запрошенному `source=2`, сохранить проверку ненулевого source ID и добавить fixture, contract-тест и live-проверку запроса с двумя показателями.

### Приёмка Epic

- Через `DataSourceAdapter` можно получить проверенный полный временной ряд поддерживаемого показателя для выбранных стран и лет.
- Внешняя форма World Bank, URL и пагинация не выходят за границу адаптера.
- Ошибка любой страницы не создаёт успешный частичный `RecordBatch`.
- Агрегаты не выдаются за страны, дубликаты и несогласованные метаданные отклоняются.
- `npm run check` и пороги покрытия проходят без обращения к живому World Bank.
- Отдельная ручная opt-in проверка подтверждает работу с актуальным API.

### Риски и открытые решения

- Node.js и `@nestjs/cli` закреплены на совместимых версиях; при обновлении CLI нужно повторно проверить требования schematics и generated diff.
- World Bank иногда возвращает предметную ошибку с HTTP 200 и меняет тип отдельных служебных полей; это учитывается runtime-схемами и fixtures.
- Полнота данных и полнота транспорта — разные понятия: `null` может быть корректным отсутствующим наблюдением, но потерянная страница должна завершаться ошибкой.
